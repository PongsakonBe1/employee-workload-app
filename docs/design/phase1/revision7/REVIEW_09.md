# Review 09 — วางแผนงาน ปฏิทิน และปุ่มคำสั่ง

6 พฤศจิกายน 2569 · branch `codex/liquid-glass-review-08` · ฐาน `fd0c5df`

ผู้ใช้อนุมัติแผนที่ปรับแล้ว: ภาพรวม/Staff เริ่มรายสัปดาห์ เลือกช่วงเองได้ อุปกรณ์เน้นจำนวนครั้งยืม ปฏิทินอิง Calendar/iCloud และปรับปุ่มตาม HIG พร้อม JD ชุดเดียวทั้งทีม เวอร์ชันแยกตามปีงบ

งานนี้เป็นต้นแบบ static HTML/CSS/JS ในโฟลเดอร์เดิม ใช้ server/public preview ที่อนุมัติ ไม่เปลี่ยน frontend production, Firestore, security rules, index, dependency หรือ deploy และไม่ push

## ผลที่เปลี่ยน

- ภาพรวมและ Staff ใช้ช่วงเดียวกัน เริ่มสัปดาห์จริงตาม Asia/Bangkok (จันทร์–อาทิตย์) เลือกวัน/สัปดาห์/เดือน/ไตรมาส/ปีงบ/custom ได้ ไตรมาสตามปีงบเริ่ม ต.ค.–ธ.ค. ปุ่มก่อนหน้า/ถัดไปเลื่อนทั้งช่วง
- เปลี่ยนตัวเลือกในฟอร์มยังไม่โหลดข้อมูล กดใช้ช่วงนี้จึงเปลี่ยนกราฟพร้อมกัน ข้อมูลจำลองมี cache ตามขอบเขต สิทธิ์ ผู้ปฏิบัติงาน และ revision ของข้อมูล เปลี่ยนกราฟ/ดูรายละเอียดไม่โหลดซ้ำ
- query contract มี start/end เสมอ, `limit: 1000`, UID filter เมื่อเป็น Staff/เลือกบุคคล, date ordering และ snapshot cursor สำหรับพัฒนาจริง ไม่มี all-history fallback จาก custom date ผิดรูปแบบ ไม่เพิ่ม document-ID order field ที่ไม่จำเป็น
- โหลดเกินชุดแรกจะแสดงว่าไม่ครบ กราฟและยอดรวมใช้เฉพาะข้อมูลที่โหลดแล้ว ผู้ใช้กดโหลดเพิ่มได้ นี่เป็นการจำลอง ไม่ใช่หลักฐานว่าลด reads ใน production แล้ว
- ภาพรวมมีแนวโน้มรายวัน/เดือน/ปีตามความยาวช่วง หัวข้อรองที่มีบันทึก การกระจายในทีม และกิจกรรมตามชั่วโมง ทุกกราฟกดดูรายการต้นทางได้ มีหน่วยกำกับ ช่วงอนาคตใช้ขีดแทนศูนย์เมื่อยังไม่มีบันทึก และระบุว่าช่วงปัจจุบันยังไม่สิ้นสุด
- Staff แสดงกิจกรรม หัวข้อรอง และวันที่มีบันทึก กรอง/ค้นรายบุคคลและส่งออกตารางที่แสดงได้ ไม่มีคะแนนจาก 50 งาน, ความยาวข้อความ หรือการใช้ Quick Log และไม่ตีความวันที่มีบันทึกเป็นวันมาทำงาน
- UID มีลำดับก่อนชื่อ ชื่อซ้ำ/UID ไม่รู้จักแยกเป็นระบุเจ้าหน้าที่ไม่ได้ การจับคู่ชื่อไม่ซ้ำใช้เฉพาะ fixtures ต้นแบบ ไม่ใช่การย้ายข้อมูลจริง งาน production ต้องตรวจงานเก่าที่ไม่มี UID แยกต่างหาก
- กิจกรรมย่อยกับชุด Combo เป็นคนละหน่วย นับชุดเฉพาะรหัสกลุ่มที่ยืนยันได้และมีเจ้าหน้าที่ ไม่เดาจำนวนครั้งบริการจาก template ID หรือเวลาเดียวกัน
- JD กลางใช้ร่วมทั้งทีม ตั้งค่าได้ทีละปี น้ำหนักต้องรวม 100% ผังหัวข้อรองอยู่ได้หนึ่งหมวด แก้ตัวอย่างการจับคู่หรือคงเป็นไม่จับคู่ได้ ไม่มี weighted performance score หรือเป้าสัดส่วน worklog ตามน้ำหนัก JD
- มีชุดอ้างอิง 2569; ไม่ใช้ข้ามปีอัตโนมัติ ปี 2570 ต้องให้ผู้ใช้ตรวจและกดใช้ชุดกลางใน session ต้นแบบก่อน ข้อมูล JD ในตารางนับเฉพาะปีงบที่ระบุและอยู่ในช่วงที่เลือก
- อุปกรณ์นับครั้งยืมรายชิ้นแยกจากคืน มี Top 5 ตารางรายชิ้นและประวัติ สถานะยืมอยู่เป็น snapshot ปัจจุบัน ข้อมูลที่จับคู่ทะเบียนไม่ได้แยกไว้ ไม่ใช้ substring จน HP-01 ตรงกับ HP-010
- สังกัดกรองตามทะเบียนปัจจุบัน มีคำอธิบายว่าประวัติไม่ได้เก็บสังกัด ณ เวลายืมครบทุกแถว สภาพคืนที่ไม่ระบุอยู่ในกลุ่มไม่ทราบ ไม่ถือเป็นสมบูรณ์ และไม่คำนวณระยะเวลายืมหากไม่มีคู่ธุรกรรมที่เชื่อถือได้
- PC calendar มี mini calendar และประเภทกิจกรรมด้านซ้ายพับได้ เมนูหลักเป็นแถบไอคอนเฉพาะหน้านี้บนจอกว้างเพื่อคืนพื้นที่ตาราง ไอคอนยังมีชื่อสำหรับ accessibility และ tooltip
- มือถือมีแถบเลือกวันและตารางรายวันเลื่อนในหน้าเดียว ไม่ซ้อน vertical scroller โหมดเดือนซ่อนแถบสัปดาห์ที่ซ้ำซ้อน มุมมองทั้งสี่ ตัวกรอง วันหยุด นำเข้า/คัดลอก และแก้รายการเดิมยังอยู่
- ปุ่มตรวจรายการใช้พื้น neutral/tonal และลูกศรไปขั้นถัดไป ปุ่มบันทึกขั้นสุดท้ายใช้สี accent และขอบแสงบาง มี press/focus/disabled states และ Reduce Motion ไม่มี blur แยกซ้อนทุกปุ่ม
- Profile Radar ยังคงหัวข้อรอง Top 8 ตาม AGENTS.md

## ข้อมูลและหลักฐานอ้างอิง

- ใช้ fixtures สังเคราะห์ที่มีอยู่และเพิ่มประวัติหกเดือนแบบ deterministic ไม่มีการอ่าน worklogs จริงหรือคัดลอกชื่อผู้ใช้/นักศึกษา/JD PDF ลง public server
- อ่าน [README บน main](https://github.com/PongsakonBe1/employee-workload-app/blob/main/README.md) ซึ่งระบุ Spark Plan ค่าการใช้งานใน README เป็นค่าประมาณ ไม่ได้ตรวจ usage console จริง
- Dashboard production มี date query/ชุดแรก 1,000 แล้ว แต่ Staff ไม่มี limit และ Equipment Health เดิมโหลดประวัติทั้งหมดก่อนกรอง client; เฟสนี้เก็บข้อกำหนดใหม่ใน query contract เท่านั้น
- [Firestore pricing](https://firebase.google.com/docs/firestore/pricing): ต้นทุนขึ้นกับเอกสาร/index entries/rules/listeners จึงไม่อ้างว่าเลือกสัปดาห์แล้วลด reads ได้เป็นอัตราคงที่
- ศึกษา [Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), [Charting Data](https://developer.apple.com/design/human-interface-guidelines/charting-data), [Materials](https://developer.apple.com/design/human-interface-guidelines/materials), [iCloud Calendar](https://support.apple.com/guide/icloud/customize-the-calendar-view-mm6b1a9ed4/icloud) และ [Calendar บน iPhone](https://support.apple.com/en-gb/guide/iphone/iphfd1054569/ios) โดยประยุกต์รูปแบบ ไม่อ้างว่าเว็บใช้ native Apple components
- น้ำหนัก JD อ้างอิง PDF ตัวอย่างปี 2569 ที่ผู้ใช้อนุญาตให้อ่าน ใช้เฉพาะหมวดทั่วไป/น้ำหนักเป็นตัวอย่างตั้งค่า ไม่มีไฟล์เอกสารต้นฉบับหรือชื่อบุคคลบน public preview

## ตรวจรับก่อนเฟสถัดไป

1. เปิดภาพรวม เปลี่ยนช่วงเอง กดใช้ และกดแท่งกราฟเทียบรายการต้นทาง
2. เปิด Staff ตั้ง JD กลางปีงบที่ต้องการ ตรวจผังจับคู่และเปลี่ยนเจ้าหน้าที่ น้ำหนักต้องไม่เปลี่ยนตามคน
3. เปิดการใช้งานอุปกรณ์ ตรวจจำนวนยืมกับประวัติ และอ่านสภาพคืนที่ไม่ทราบแยกจากสมบูรณ์
4. ลอง calendar ทั้ง PC/mobile รวมวันหยุด ตัวกรอง และปุ่มตรวจรายการ/บันทึกใน Quick Log
5. ยังต้อง UAT บน Safari/iPhone, Android และเครื่องสแกนจริง การย้ายเข้า production และวัด reads จริงเป็นขอบเขตถัดไปที่ต้องรับอนุมัติ
