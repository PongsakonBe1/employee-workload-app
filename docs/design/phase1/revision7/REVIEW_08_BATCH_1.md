# Review 08 ชุดแรก — แก้การใช้งานก่อนปรับภาพ

วันที่ 5 พฤศจิกายน 2569 · branch `codex/liquid-glass-review-08` · ฐาน `958f68b`

ผู้ใช้อนุมัติชุดแรกของแผนรอบใหม่แล้ว งานทั้งหมดเป็นต้นแบบ HTML/CSS/JS และข้อมูลสังเคราะห์ใน `docs/design/phase1/revision7` ยังไม่ได้แก้ frontend production, push, deploy หรือติดตั้งแพ็กเกจ

## สิ่งที่แก้

- หัวข้อรองในฟอร์มบันทึกเอง: เปิด dialog กลางจอ PC; มือถือใช้ sheet ตามเดิม เริ่ม focus ช่องค้นหาและรักษาร่างผู้รับบริการ/รายละเอียดเมื่อเลือกงาน
- Combo: ทุกชุดเริ่มว่าง รวมถึง Template ที่เคยตั้งบันทึกทั้งชุด ผู้ใช้เลือกเอง ใช้เลือกทั้งหมด/ล้างการเลือกได้ ตรวจจำนวนตามที่เลือกจริง และไม่จำการเลือกจากการเปิดครั้งก่อน
- ฟอร์มวันที่ เวลา และข้อความ: จำกัดความกว้างตามพื้นที่ grid; ขนาดตัวอักษร input บนมือถือ/จอสัมผัสอย่างน้อย 16px โดยไม่ห้าม pinch zoom
- ผู้รับบริการที่จำเป็น: เมื่อว่างหรือมีแต่ช่องว่าง ให้แสดงข้อความใกล้ช่อง พร้อม focus และ scroll เข้าในพื้นที่มองเห็น; ช่องที่ Template ระบุว่าไม่บังคับยังเว้นว่างได้
- เพิ่มการติดตามการเปลี่ยนขนาด visual viewport เพื่อช่วยเลื่อนช่องที่กำลังกรอกเมื่อคีย์บอร์ดบัง ต้องตรวจพฤติกรรมบนเครื่องจริงเพิ่ม
- ประวัติงาน Calendar: กดวันแล้วเปิดรายการของวันนั้น เลือกดูรายละเอียดและย้อนกลับรายการของวันได้ โดยไม่เปลี่ยนโหมด เดือน ช่วงวันที่ หรือคำค้น และใช้สิทธิ์/ตัวกรองเดิม
- ห้องชั้น 3 และ 4: ใช้ modal แบบกริดเลือกอุปกรณ์ มีสถานะปัจจุบันและคำสั่งเปิด/ปิดชัดเจน กดแล้วบันทึกครั้งเดียวและปิด modal พร้อม persistent Undo ตามข้อกำหนดเดิม
- ผู้ใช้ยืนยันเพิ่มเติม: ช่องผู้รับบริการใน Smart Quick Log ยืมหูฟัง ปลั๊กไฟ และ USB เป็นรหัสนักศึกษาตัวเลข 0–9 จำนวน 13 หลัก ใช้ข้อความเพื่อรักษาศูนย์นำหน้าและ `inputmode="numeric"` สำหรับมือถือ แจ้ง error และ focus ช่องเมื่อผิด ไม่ตัด/แปลงข้อความผิดภาษา ไม่ตัดรหัสยาวเกินให้กลายเป็นรหัสที่ดูถูกต้อง และไม่บันทึกเองเมื่อเครื่องสแกนส่ง Enter
- แก้ regression หลังเทียบ `SmartEquipmentModal.js` เดิม: ตอนคืนใช้รหัสจากรายการยืม ไม่ขอให้กรอกซ้ำ แสดงรหัสแบบอ่านอย่างเดียวพร้อมวันที่/เวลา และรักษารหัสนั้นในบันทึกคืน หากสลับไปอุปกรณ์ว่างต้องล้างรหัสก่อนรับผู้ยืมคนใหม่ ข้อมูลผู้ยืมใน fixture เป็นข้อมูลสังเคราะห์ทั้งหมด
- แก้ regression ของ suggestion: นำ `commentSuggestionMap` ทั้ง 14 หมวดจาก `frontend/lib/commentSuggestions.js` เดิมมาใช้โดยตรง ไม่ใช้คำแนะนำทั่วไป 3 ข้อแทน แสดงตามหัวข้อรอง เลือกแล้วใส่รายละเอียดและบันทึกร่าง รักษาข้อความที่แก้เองเมื่อเปลี่ยนหัวข้อรอง ใช้ endpoint ที่คืนเฉพาะ mapping แบบ static ไม่อ่านประวัติหรือ Firestore
- เพิ่ม `flow-fixes.js` และ `flow-fixes.css` หลังฐาน R07 เพื่อจำกัดขอบเขตของ prototype adapter; เมื่อพอร์ตเข้า production ต้องแก้ใน component ต้นทางและทดสอบใหม่

## ผลตรวจจริง

ใช้ Playwright runtime ที่มีอยู่และ Edge แบบ headless พร้อม profile ชั่วคราว ไม่มีการติดตั้ง dependency เพิ่ม

| คำสั่ง | ผล |
|---|---|
| `node --check` สำหรับไฟล์ JS/CJS ที่เพิ่มหรือแก้ | ผ่าน |
| `node docs/design/phase1/revision7/verify-flow-fixes.cjs <playwright-module> <edge-executable>` | ผ่าน 22 กลุ่ม รวมการคงร่าง, ไม่เขียนเมื่อข้อมูลไม่ครบ, จำนวนที่เลือก, ตัวกรอง Calendar, staff scope, Undo, รหัสนักศึกษาสำหรับอุปกรณ์ทั้ง 3 ประเภท/มือถือ, คืนโดยเติมรหัสผู้ยืมเดิม และ suggestion ทั้ง 14 หมวด/การ reflow หลายขนาดจอ |
| `node docs/design/phase1/revision7/verify.cjs <playwright-module> <edge-executable> --interactions` | ผ่าน flow เดิม 11 กลุ่ม รวม offline และ Undo เมื่อมีสถานะใหม่แทรก |
| `node docs/design/phase1/revision7/verify.cjs <playwright-module> <edge-executable> --accessibility` | ผ่าน 300 สถานะ: 30 หน้า × Light/Dark × 5 ขนาด/บริบท และตรวจเสริมอีก 5 บริบท ไม่มี failure/error |

ชุดใหม่ตรวจฟอร์มที่ความกว้าง 375, 390, 430, 768 และ 1440px ทั้งสองธีม ชุด accessibility ตรวจ 375, 390, 768, 1024 และ 1440px รวมข้อความขยาย dialog และการตั้งค่าการเคลื่อนไหว ไม่ใช่การรับรอง WCAG ทั้งระบบ

ผล accessibility 300 สถานะข้างต้นเป็นฐาน commit `b23645e` ก่อนเพิ่ม validation รหัสนักศึกษา ส่วน flow เดิม 11 กลุ่มได้ตรวจซ้ำหลังคืนพฤติกรรมเดิมรอบล่าสุด หลังแก้เพิ่มเติมได้ตรวจชุด flow 22 กลุ่มซ้ำ รวมการพิมพ์/วางรหัสว่าง 12/14 หลัก ภาษาไทย อังกฤษ เลขไทย รูปแบบเลขยกกำลัง และช่องว่าง ตรวจยืม/คืน การยกเลิกก่อนคืน การเก็บศูนย์นำหน้า และความกว้าง/ตัวอักษรช่องกรอกบนมือถือ การตรวจรูปแบบไม่ใช่การยืนยันตัวบุคคลหรือสถานะนักศึกษา

หลักฐานอยู่ใน `output/playwright/ux-phase1/revision8/`: `flow-report.json`, `validation-summary.json`, ภาพ picker, Calendar รายวัน, ฟอร์มมือถือ, modal ห้อง, ช่องรหัสนักศึกษา และภาพ Combo จาก public preview ที่เปิดตรวจจริง

## รายการรอ

1. Safari บน iPhone จริง: เปิดฟอร์มบันทึกเองและฟอร์มใน sheet ตรวจ date/time, การ focus, คีย์บอร์ด, การหมุนเครื่อง และการ zoom ยังยืนยันว่าอาการ iOS หายทั้งหมดไม่ได้จาก Chromium emulation
2. รูปแบบ barcode ยืนยันและเพิ่ม validation แล้ว เหลือทดลองกับเครื่องสแกนจริงซึ่งอาจส่งอักขระต่อท้ายต่างกัน กรณีผิดจะคงข้อความให้ตรวจแก้ ไม่แปลงหรือตัดทิ้ง
3. รอ Tech Lead ตรวจรับชุดแรกก่อนเริ่มชุดสอง: สี/วัสดุ/ไอคอน/motion และ Calendar Day/Week/Month วันหยุด จากนั้นจึงชุด Analytics

## ทดลองตรวจรับ

- บันทึกงาน → กรอกเอง → กรอกผู้รับบริการ/รายละเอียด → เปิดหัวข้อรอง → ค้นหาและเลือก → ร่างต้องยังอยู่และ picker ไม่ไปชิดขวา
- บันทึกด่วน → Combo → ต้องเห็น 0 รายการ → เลือก 1 งานแล้วกดตรวจโดยไม่กรอกผู้รับบริการ → focus ต้องไปที่ช่องนั้น → กรอกแล้วบันทึกต้องเพิ่มเพียง 1 รายการ
- ห้องชั้น 3/4 → ยกเลิกต้องไม่เกิดงาน → เปิด/ปิดห้องแล้วกดเลิกทำต้องคืนสถานะเดิม
- ยืมอุปกรณ์ → เลือกอุปกรณ์ → กรอกรหัสผิดภาษาหรือไม่ครบ → ต้องแจ้งและ focus ช่อง โดยไม่บันทึก → แก้เป็นตัวเลข 13 หลัก → ยืนยันยืมได้ ช่องผู้รับบริการในงานประเภทอื่นไม่ได้เปลี่ยนเป็นรหัส 13 หลัก
- ตอนคืนเลือกอุปกรณ์ที่กำลังยืม → ต้องเห็นรหัสผู้ยืมจากข้อมูลเดิม ไม่ต้องกรอก → ตรวจสภาพ/ยืนยันคืนได้ และไม่เปลี่ยนรหัสผู้ยืมของรายการนั้น
- กรอกเอง → เลือกหัวข้อรอง `ติดตั้ง Software` → เห็น Adobe Creative Cloud, MATLAB, Microsoft 365, SolidWorks, ESET และ Foxit PDF ตามไฟล์เดิม เลือกแล้วแก้รายละเอียดต่อได้
- ประวัติงาน → ปฏิทิน → กดวัน → รายละเอียด → กลับ/ปิด → ยังอยู่ปฏิทินและช่วงวันที่เดิม
