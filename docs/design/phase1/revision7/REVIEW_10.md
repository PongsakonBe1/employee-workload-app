# Review 10 — พื้นหลัง การเลื่อน และการอ่านภาพรวม

6 พฤศจิกายน 2569 · branch `codex/liquid-glass-review-08` · ฐาน `3555f29`

ผู้ใช้อนุมัติให้แก้พื้นหลังมือถือ ปรับ scrollbar/tooltip และจัดลำดับข้อมูลหน้าภาพรวมจากข้อเสนอ Review 09 งานนี้อยู่ในต้นแบบ static เดิม ใช้ข้อมูลสังเคราะห์ ไม่แก้ Next.js production, Firestore, dependencies หรือ deployment และไม่ push

## แผนและเกณฑ์รับงาน

1. แก้ CSS ที่ทับ gradient บนมือถือ เพิ่มชุดสีฟ้า–เขียวจากโค้ดแอปเดิม และคงตัวเลือกฟ้า–ม่วงกับพื้นเรียบ
2. ใช้ scrollbar บางที่ยังลากได้และเลื่อนด้วย keyboard ตามระบบ แก้แนวนอนที่ล้นใน compact sidebar พร้อม tooltip ที่ไม่ถูกกรอบตัด
3. ให้ภาพรวมเน้นจำนวนและแนวโน้มก่อน แยกข้อมูลรองไว้ดูเพิ่มเติม เปลี่ยนแถบเปรียบเทียบบุคลากรเป็นรายชื่อทีม เพื่อไม่สื่อการจัดอันดับคุณภาพงาน
4. ตรวจ Light/Dark, จอเล็ก, keyboard, Reduce Motion, ยอดกราฟกับข้อมูลต้นทาง และ flow เดิม เก็บผลจริงแยกจาก UAT ที่ยังไม่ได้ทำ

ความเสี่ยงหลักคือ CSS ร่วมกระทบหน้าอื่น การซ่อนแถบเลื่อนทำให้หาเนื้อหาไม่พบ และการย่อสรุปทำให้ตีความจำนวนเป็นภาระงาน ป้องกันด้วย native scrolling, ข้อความกำกับหน่วย/ข้อมูลที่โหลดแล้ว, drill-down เดิม และตรวจ regression ย้อนกลับได้ด้วย diff/commit เฉพาะต้นแบบ

## สิ่งที่เปลี่ยนและเหตุผล

- ลบ mobile rule ที่บังคับ `.wallpaper` เป็นสีพื้นเดียวด้วย `!important` ทุกชุดพื้นหลังจึงใช้ได้ทั้ง PC และมือถือ
- ชุดเริ่มต้น “ฟ้า–เขียวเดิม” ใช้ gradient Light จาก `frontend/app/globals.css` ส่วน Dark ปรับโทนให้กลมกลืนและอ่านข้อมูลได้ ไม่ใช้สี Light ตรง ๆ บนพื้นมืด
- เลือกพื้นหลังได้จากรูปแบบการแสดงผล/ตั้งค่า คงร่างฟอร์มและ focus หลังเปลี่ยน ตัวเลือกอยู่ใน session ตรวจแบบ ยังไม่บันทึกลงบัญชีหรือ localStorage
- พื้นข้อมูลยังเป็นผิวอ่านชัด ใช้กระจกกับ navigation/controls ตามแนวทางวัสดุ ไม่เพิ่มภาพภายนอกหรือเอฟเฟกต์พื้นหลังเคลื่อนตลอดเวลา
- scrollbar บางลงและ track โปร่ง แต่ยังมี indicator และลากได้ตาม browser ไม่ใช้ `scrollbar-width:none` หรือปิด scrolling ทั้งระบบ รองรับ Forced Colors
- compact sidebar ลด padding ที่ไม่จำเป็น ปิดเฉพาะการล้นแนวนอนในเมนูซึ่งต้องวางไอคอนเป็นคอลัมน์เดียว รักษาการเลื่อนแนวตั้งเมื่อเปิดเครื่องมือเพิ่ม และใช้ focus ring ด้านในเพื่อไม่ถูกตัด
- tooltip เป็นชั้นแยกนอก sidebar แสดงหลัง hover 320ms หรือเมื่อ focus ด้วย keyboard ย้าย pointer ไปอ่านข้อความได้ กด Escape เพื่อปิด และปิดเมื่อเลื่อน/คลิก/เปลี่ยนหน้า/เปิด dialog มี fade/translate 120ms และปิด motion เมื่อผู้ใช้ลดการเคลื่อนไหว ตัวเลขเวลานี้เป็นการเลือกของโครงการ ไม่ใช่ค่าบังคับจาก Apple
- ภาพรวมรวม KPI เป็นสรุปเดียว ให้กิจกรรมที่บันทึกเด่นที่สุด ตามด้วยแนวโน้มเต็มความกว้าง มีประโยคบอกวันที่มีบันทึกสูงสุดจากข้อมูลที่โหลดแล้ว รองรับวันเสมอและข้อมูลว่าง
- แสดงหัวข้อรองที่พบบ่อย 5 รายการก่อน เปิดรายการทั้งหมดได้โดยไม่โหลดข้อมูลใหม่ ทุกแถบยังเปิดรายการต้นทางได้ Profile Radar Top 8 `minorTask` ไม่เปลี่ยน
- ทีมแสดงตามลำดับรายชื่อคงที่ พร้อมจำนวนรายการ/หัวข้อ/วันที่มีบันทึก ไม่มีแถบจัดอันดับตามจำนวน ปุ่มชื่อเปิดรายการต้นทางได้ และข้อมูลไม่ทราบเจ้าหน้าที่ยังแยกชัดเจน
- บริบท Combo/JD/ช่วงชั่วโมงเปิดจาก disclosure เพื่อลดความหนาแน่น ยังคงคำเตือนว่าจำนวนบันทึกไม่ใช่คะแนน ระยะเวลา หรือความยากของงาน
- ช่วงข้อมูลเริ่มรายสัปดาห์ ระบบ Apply/cache/query contract จาก Review 09 คงเดิม การเปลี่ยนการแสดงผลไม่ได้สร้าง data load เพิ่มในต้นแบบ

## หลักอ้างอิง

- [Charting data](https://developer.apple.com/design/human-interface-guidelines/charting-data): กราฟทั่วไปที่อ่านคุ้นเคย ความสม่ำเสมอ และรายละเอียดที่เปิดดูเพิ่มเติม ไม่เพิ่มชนิดกราฟเพื่อความหลากหลายเพียงอย่างเดียว
- [Scroll views](https://developer.apple.com/design/human-interface-guidelines/scroll-views): ต้องรู้ว่ามีเนื้อหาให้เลื่อนและรักษา gestures/keyboard ของระบบ
- [Offering help](https://developer.apple.com/design/human-interface-guidelines/offering-help): คำอธิบายสั้นและสัมพันธ์กับ controls
- [Motion](https://developer.apple.com/design/human-interface-guidelines/motion): feedback ที่กระชับ มีหน้าที่ และเคารพ accessibility preferences
- [Materials](https://developer.apple.com/design/human-interface-guidelines/materials): แยกชั้น navigation/controls จากเนื้อหาที่อ่าน

ประยุกต์ HIG บนเว็บ ไม่อ้างว่าเป็น native Apple components หรือได้รับการรับรอง HIG/WCAG ทั้งระบบ

## UAT กับทีมก่อนเริ่มเฟสถัดไป

ใช้ข้อมูลตัวอย่างเดียวกันและให้แต่ละคนลองด้วยอุปกรณ์ที่ใช้งานจริง โดยเริ่มจากคำถาม ไม่สอนวิธีกดก่อน

| โจทย์ | สิ่งที่ตรวจ |
|---|---|
| สัปดาห์นี้มีบันทึกทั้งหมดกี่รายการ และวันใดมากที่สุด | อ่านหน่วย ช่วงเวลา และข้อความสรุปได้ ไม่ตีความว่าเป็นชั่วโมงทำงาน |
| งานประเภทใดเกิดบ่อย และเปิดดูตัวอย่างรายการนั้น | หา Top tasks และ drill-down ได้ |
| หาบันทึกของเจ้าหน้าที่ที่ระบุ | ใช้รายชื่อทีมได้ และไม่มองจำนวนเป็นคะแนนคุณภาพ |
| เปลี่ยนเป็นช่วงเดือน แล้วกลับสัปดาห์นี้ | เข้าใจ Apply และทุกส่วนใช้ขอบเขตเดียวกัน |
| เปิดเครื่องมือท้าย sidebar บน PC และเปลี่ยนพื้นหลังบนมือถือ | หาเนื้อหาที่เลื่อนได้ อ่าน tooltip และเห็นสีพื้นหลังจริง |

บันทึกคำตอบที่ถูก/ผิด จุดที่ลังเล การย้อนกลับ และคำอธิบายความหมายของตัวเลขจากผู้ใช้ก่อนปรับรอบถัดไป ยังไม่ได้ทำ UAT กับทีม 8 คน จึงยังยืนยันความเข้าใจจริงไม่ได้

ข้อจำกัด: browser automation ใช้ Edge และจำลอง viewport/touch ไม่แทน Safari/iPhone/Android หรือเครื่องสแกนจริง ไม่มีการวัด Firestore reads หรือประสิทธิภาพ production ในเฟสนี้
