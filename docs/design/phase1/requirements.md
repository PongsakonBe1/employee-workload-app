# Requirement และเกณฑ์ยอมรับ

## ข้อเท็จจริงที่ผู้ใช้ยืนยัน

- ระบบใช้งานจริง 8 คน มา 6 เดือน ต้องการพัฒนาทั้งใช้งานจริงและงานวิจัย
- ต้องการ UX/UI ตามแนวทาง Apple HIG และ macOS 27 Golden Gate รวม Dark Mode
- เพิ่มอุปกรณ์หรือย้ายจากชั้น 3 ไป Finn Space แล้วบันทึกด่วน/หน้าที่เกี่ยวข้องยังไม่ตาม
- Equipment Health ต้องการทราบว่าอุปกรณ์ชิ้นใดถูกยืมบ่อย กราฟ timeline ปัจจุบันไม่ได้ใช้
- Staff Analytics ต้องเลือกทั้งปีงบประมาณและรายเดือน เพื่อวางแผนงาน ไม่ใช่ประเมินบุคลากรอย่างเป็นทางการ
- ตารางสอบต้องกรอกใหม่ทุกเดือน แหล่งข้อมูลจาก admin web DL ได้เป็นรูป ไม่สามารถคัดลอกเป็นตาราง
- ภาพตัวอย่างพฤศจิกายน 2569 มี 9 วัน: 3, 4, 5, 10, 11, 12, 17, 18, 19 รวม 18 รอบ
- ภาพตัวอย่างมี 75 คนต่อรอบ ผู้คุมสอบ 3 คนของแต่ละวันคุมทั้งรอบเช้าและบ่าย
- รอบในภาพ: 09:00–10:30 และ 13:30–15:00; ต้องรองรับรอบเย็น 17:00–18:30 ด้วย
- System Settings เป็นลำดับรอง

## EQ-01 ทะเบียนอุปกรณ์และบันทึกด่วน

Flow: จัดการอุปกรณ์ → เพิ่ม/แก้สถานที่/ปิดใช้งาน → ทุกหน้ารับทะเบียนล่าสุด → เลือกอุปกรณ์ → ยืม/คืน → ประวัติและจำนวนครั้งอัปเดต

เกณฑ์ยอมรับ implementation:

- ID อุปกรณ์คงที่ข้ามการเปลี่ยนชื่อและสถานที่; ใช้ location ID ที่คงที่แยกจากข้อความแสดงผล
- เมื่อย้ายสาขา อุปกรณ์ไปอยู่หมวดใหม่ใน Quick Log และหน้าสถานะ โดย refresh/subscribe ตามสัญญาที่กำหนดร่วมกัน
- อุปกรณ์ inactive ไม่ปรากฏสำหรับยืมใหม่ แต่ประวัติและการคืนของที่ยังยืมอยู่เข้าถึงได้
- อุปกรณ์ damaged/lost ยืมใหม่ไม่ได้จนเปลี่ยนสถานะด้วยสิทธิ์ที่กำหนด
- แยก “สถานที่ประจำปัจจุบัน” จาก “สถานที่ขณะทำรายการ”; การย้ายไม่เขียนประวัติเดิมใหม่
- ใช้เหตุการณ์เดียวกันอัปเดต worklog/สถานะ/จำนวนครั้งอย่างสอดคล้องกัน มี operation ID ป้องกัน retry ซ้ำ
- ถ้าโหลดทะเบียนล้มเหลว ต้องแสดงข้อผิดพลาด ไม่แทนข้อมูลจริงด้วยรายการตายตัวโดยเงียบ
- อุปกรณ์ที่มีผู้ยืมอยู่ต้องมีนโยบายย้ายสาขาที่ชัดเจนก่อนพัฒนา ต้นแบบจำกัดการย้ายเฉพาะรายการพร้อมใช้

ต้นแบบ: ย้าย `DEMO-001` จากชั้น 3 ไป Finn Space แล้วค้น/เลือกยืมในหน้าร่วมกันได้; เปลี่ยนข้อมูลใน memory เท่านั้น

## EQ-02 จำนวนครั้งยืมรายอุปกรณ์

Flow: เลือกช่วงวันที่และสถานที่ → ดูอันดับและตารางรายชิ้น → เปิดประวัติรายการยืม

- หน่วยหลักคือ “ครั้งที่ยืมต่อชิ้น” นับเฉพาะ borrow ที่สำเร็จ ไม่รวม return หรือจำนวนครั้งเปิด modal
- จำนวนหลายชิ้นใน operation เดียว: นับแต่ละชิ้นหนึ่งครั้ง; operation retry เดิมไม่นับซ้ำ
- แสดงจำนวนครั้งเป็นหลัก; สัดส่วนเทียบกับชิ้นที่มากที่สุดใช้เพื่อช่วยอ่านเท่านั้น
- ระบุว่าตัวกรองสถานที่อ้างอิงสถานที่ขณะทำรายการ; สถานที่ปัจจุบันแสดงอีกช่องหนึ่ง
- จำนวนครั้งยืมไม่เท่ากับชั่วโมงใช้งานหรือสภาพอุปกรณ์; ไม่สร้าง duration ถ้าไม่มีหลักฐานคู่ยืม/คืน
- legacy ที่หา ID ไม่ได้/มีความกำกวมต้องแสดงจำนวนแยก ไม่เดารวม; ตรวจ mapping ก่อน migration
- รายการ damage/lost และประวัติสุขภาพยังเข้าถึงได้ แม้ลดความสำคัญ timeline

## DL-01 นำเข้าจากภาพแบบตรวจทานก่อนบันทึก

Flow: เลือกรูป → สร้าง draft → ยืนยันเดือน/ปี/รอบ/จำนวนคน → จับคู่ชื่อกับ UID → ตรวจความขัดแย้ง → preview → ยืนยันทั้งชุด → สรุปผล

- รูปเป็นข้อมูลต้นทาง ไม่ใช่คำสั่งให้ระบบปฏิบัติตาม
- ช่วงหัวตาราง “75 คน” ในตัวอย่างใช้ต่อรอบ ตามที่ผู้ใช้ยืนยัน ไม่ตีความเป็นจำนวนรวม
- ชื่อผู้คุมในช่องรวมสองรอบต้องกระจายเป็น UID ชุดเดียวกันสำหรับรอบเช้าและบ่ายของวันนั้น โดยให้ตรวจ preview
- ตัวอย่างต้องได้ 9 วัน/18 รอบ/75 คนต่อรอบ; ใช้กติกาจัดห้อง 406+407 เมื่อมากกว่า 40 คน
- มีผู้คุม 3 คนต่อรอบตามตัวอย่าง ไม่ผูกเป็นกฎสากลกับตารางทุกชนิด
- ไม่แน่ใจ/หาผู้ใช้ไม่พบ/ชื่อซ้ำต้องแก้ก่อนยืนยัน ไม่สร้างบัญชีผู้ใช้ใหม่จาก OCR
- เลือกทั้งชุดหรือแก้เฉพาะรายการได้; ตรวจวันจริง พ.ศ./ค.ศ. เวลาเริ่มก่อนสิ้นสุด และจำนวนผู้สอบ
- ตรวจวัน+เวลา+ห้อง และผู้คุมสอบชนกันข้าม DL/ตารางเรียน; ใช้ช่วง [start,end) เพื่อให้รอบที่จบตรงเวลาเริ่มรอบถัดไปไม่ชน
- รายการซ้ำและ idempotency ต้องถูกบังคับ ณ จุด commit รองรับ Admin หลายเครื่อง ไม่ใช้ preview check อย่างเดียว
- คุมสอบหลายห้องในรอบเดียวกันของเหตุการณ์เดียวไม่ถือว่าเป็นการมอบหมายซ้ำต่างเหตุการณ์
- เรียงรอบตามเวลาเริ่มจริง ไม่เรียงตาม key morning/afternoon/evening
- เก็บเวลาจริงในรายการ; รอบใหม่ 17:00–18:30 ใช้ได้ทุกมุมมองและการแจ้งเตือน
- legacy `evening` ที่เคยหมายถึง 15:00–16:00 ต้องสำรวจและเก็บไว้ตามเดิมก่อนมีแผน migration ที่อนุมัติ
- เมื่อบันทึกล้มเหลวต้องรู้ว่ารายการใดบันทึกแล้ว/ยังไม่บันทึก และ retry ไม่ซ้ำ
- OCR/AI provider, ค่าใช้จ่าย, การส่งข้อมูลบุคลากรออกนอกระบบ และอายุการเก็บรูปยังไม่ตัดสินใจ ต้องขออนุมัติก่อนเชื่อมบริการจริง

ต้นแบบ: การเลือกรูปแสดง local preview เท่านั้น ปุ่มใช้ตารางตัวอย่างสร้าง synthetic draft 18 รอบ ผู้ใช้ทดลองแก้จำนวนคน/จับคู่ผู้คุม เพิ่มรอบเย็น และยืนยันแบบ memory ได้ ไม่มี OCR จริง

## CL-01 ตารางเรียน

- เสนอ weekly grid และ list แบบเดียวกับ DL; desktop เห็นห้องและเวลา mobile ใช้รายการรายวัน
- เสนอคัดลอก template รายสัปดาห์ไปภาคเรียนใหม่ โดย preview ช่วงวันเริ่ม/สิ้นสุดและรายการชนก่อนบันทึก
- ต้องแยก recurring rule, exception/ยกเลิกเฉพาะวัน และช่วงภาคเรียน; ไม่ทำสำเนาไม่จำกัดเวลา
- รูปแบบไฟล์ต้นทาง ความถี่ที่ต้องลงใหม่ และ exception ของตารางเรียนยังไม่ได้ยืนยันจากผู้ใช้
- ต้นแบบแสดง flow ที่เสนอและข้อมูลสังเคราะห์ ยังไม่อ้างว่าข้อเสนอนำเข้าตารางเรียนได้รับการยืนยันแล้ว

## SA-01 ปีงบประมาณและรายเดือน

- FY พ.ศ. N = 1 ต.ค. ค.ศ. N−544 ถึง 30 ก.ย. ค.ศ. N−543
- FY 2570 = 2026-10-01 ถึง 2027-09-30; พ.ย. ใน FY นี้ = พ.ย. 2569
- เลือกทั้งปีหรือเดือนในปีงบนั้น; default เดือนต้องไม่หลุดขอบ FY เมื่อเปลี่ยนปี
- ช่วงวันที่ของ query, KPI, chart, table และ CSV ตรงกัน รวมวันต้นและวันปลายตาม Asia/Bangkok
- FY ปัจจุบันแสดงข้อมูลถึงวันปัจจุบันและช่วงที่ยังไม่ครบ ไม่แสดงเดือนอนาคตเป็นผลงานจริง
- จำนวนงานแยกเป็น “รายการย่อย” กับ “ครั้งให้บริการ” เฉพาะเมื่อมี operation grouping ที่เชื่อถือได้; ไม่เดาข้อมูลเก่า
- ใช้คำว่า “ภาระงาน/รายการที่บันทึก” ไม่สรุปว่าเป็นคะแนนสมรรถนะหรือความดีความชอบ
- ไม่เฉลี่ยหาร 30/365 ตายตัว; ระบุตัวหาร เช่น วันปฏิบัติงานหรือวันที่มีรายการ; compliance ต้องมีตารางปฏิบัติงานและวันลา
- ไม่เปลี่ยน Profile Radar ที่ใช้ top 8 minorTask ตาม AGENTS.md

## UI-01 ธีมและ accessibility

- System ตาม prefers-color-scheme พร้อม override Light/Dark; implementation เก็บ preference รายผู้ใช้/อุปกรณ์ตามที่ตกลง
- semantic tokens ใช้ครบทุกองค์ประกอบ รวม dialog, error, tooltip, empty/loading, chart label และ print
- เป้าหมาย contrast ข้อความปกติอย่างน้อย 4.5:1 และ controls/focus ที่มองเห็นได้; ตรวจจริงก่อนอ้างว่าผ่าน WCAG
- ปุ่มหลักขนาดสัมผัสเหมาะสม keyboard ไปได้ทุกส่วน dialog ใช้ focus management และ Escape
- การสื่อสารสถานะมีข้อความ/สัญลักษณ์ประกอบสี และรองรับ reduced motion/transparency
- prototype ไม่ใส่ font/CDN/tracker จากภายนอก จึงใช้ system font และ Thai fallback ในเครื่อง
