## วิธีทดลอง

เปิด [ปฏิทิน develop](https://northwest-revised-domains-varies.trycloudflare.com/dev/calendar) แล้วเลือก **พื้นที่ทดลองนำเข้า → นำเข้าตาราง → ตารางสอบ DL · รูปภาพ**

1. เลือก PNG/JPEG แล้วกด **อ่านตารางจากภาพ** ดูต้นฉบับประกอบได้
2. ตรวจวันและเวลา จำนวนคนต่อรอบ และภาคเรียน ในส่วน **ตรวจชื่อและจับคู่ผู้คุม** แก้ชื่อ OCR ให้ถูกแล้วกด **ใช้ชื่อนี้ชั่วคราว** หากไม่มีชื่อในรายชื่อ A–H ระบบเลือกชื่อชั่วคราวนั้นให้ทุกรอบที่พบชื่อเดียวกัน หรือเลือกผู้คุมที่มีแล้วจากช่องด้านล่าง สามารถแก้ผู้คุมแยกแต่ละรอบหรือเลือก “ไม่มีชื่อในช่องนี้” อย่างชัดเจน
3. ช่องที่อ่านไม่ได้แสดงภาพตัดแถววัน/เวลาเพื่อแก้เอง ช่องที่จัดรูปแบบหรืออ่านซ้ำมีข้อความให้ตรวจเทียบต้นฉบับ ไม่มีการเติมรอบเย็นที่ไม่อยู่ในภาพ
4. กดตรวจจุดที่ต้องแก้เพื่อโฟกัสช่องนั้น ยืนยันว่าตรวจรายการแล้ว จากนั้นกดเพิ่มทั้งชุด หากมีรายการซ้ำ/ห้องชนหรือข้อมูลยังไม่ครบ จะไม่เพิ่มบางส่วน
5. เลิกทำด้วย **Undo / เลิกทำ** ชุดตัวอย่างและ sandbox มีสถานะ/Undo แยกกัน

ตัวเลือก PDF ตารางเรียนเดิมยังอยู่ในหน้าต่างเดียวกัน รองรับการเพิ่มรายการเองภายหลังตามเดิม ข้อมูลทดลองและรายชื่อชั่วคราวอยู่ในหน่วยความจำ ไม่ใช่ข้อมูลถาวร รีเฟรชหน้าแล้วข้อมูลทดลองจะหาย

## ข้อมูลและกติกา

- 75 หมายถึง **คนต่อรอบ** เป็นค่าตั้งต้นที่ทีมยืนยันและแก้ได้ ไม่ใช่จำนวนรวมทั้งเดือน มากกว่า 40 ใช้ 406 + 407 ตามเกณฑ์ preview เดิม จำนวนไม่เกิน 40 ใช้ 406 เฟสนี้ไม่ได้เพิ่มนโยบายความจุห้องหรือ CEM จาก production manager
- ใช้วัน/เวลาที่อ่านจากแต่ละแถว ไม่มีการแทนรอบบ่ายด้วยค่า default และรองรับเวลาเย็น 17:00–18:30 เมื่อระบุในภาพ
- ปีสั้นแบบไทย `69` แปลงเป็น 2569 / 2026 วันและเวลาเก็บเป็น date-only / HH:MM ตรวจวันจริงและเวลาสิ้นสุดในวันเดียวกัน
- ตารางต้นฉบับที่รองรับมีเส้นแนวนอน/แนวตั้งชัดเจน คอลัมน์วัน/เวลาและผู้คุม 3 ช่อง หัวผู้คุมรวม เชื่อมชื่อในช่องเดียวกันกับหลายรอบของวันนั้น
- ผู้คุมต้องเลือกให้ครบตามช่องก่อนยืนยัน ไม่จับคู่ชื่อคล้ายกันอัตโนมัติ ไม่ยอมให้เลือกคนเดียวซ้ำภายในรอบเดียวกัน และต้องมีผู้คุมอย่างน้อยหนึ่งคน
- ตรวจห้องชนทั้งกับตารางเรียนรายสัปดาห์ รายการสอบเดิม และรอบภายในชุดใหม่ ตรวจซ้ำอีกครั้งก่อน commit
- รายชื่อตั้งต้นเป็นเจ้าหน้าที่สมมติ A–H เมื่อไม่มีชื่อที่ตรงกับภาพ ผู้ใช้เพิ่มชื่อที่ตรวจแล้วเข้า roster ชั่วคราวได้โดยกดปุ่มอย่างชัดเจน ไม่เพิ่มชื่อจาก OCR อัตโนมัติ ไม่ hardcode รายชื่อจริงลง fixture ไม่สร้างบัญชีผู้ใช้ และไม่เปิด Firebase การเชื่อม UID/รายชื่อจริงและ schema ของ production DL manager ยังอยู่นอกเฟสนี้
- ชื่อเดียวกันหลังปรับช่องว่าง/ตัวพิมพ์จะใช้ ID เดิม ชื่อคล้ายกันหรือวงเล็บชื่อเล่นต่างกันยังเป็นคนละคน การแก้ช่องชื่อ OCR จะล้าง mapping เดิมให้ยืนยันใหม่ รายละเอียดปฏิทินและฟอร์มแก้ไขใช้ roster ชุดเดียวกัน
- รายชื่อชั่วคราวอยู่ได้เมื่อปิด/เปิด import และสลับหน้าในแท็บเดิม ไม่เก็บใน localStorage/sessionStorage รีเฟรชแล้วหาย Undo การนำเข้าลบเฉพาะรอบสอบ รายชื่อชั่วคราวยังเลือกใช้ซ้ำได้ในแท็บนั้น

## OCR และข้อมูลส่วนบุคคล

ติดตั้ง `tesseract.js@7.0.0` พร้อม `@tesseract.js-data/tha@1.0.0` และ `@tesseract.js-data/eng@1.0.0` ใช้ integer language models เก็บ worker, core, language data และ license notices ไว้ใน `frontend/public/dev-ocr/` ซึ่งไม่ commit ไฟล์ binary

`node scripts/dev-ui.mjs` เตรียม assets จากแพ็กเกจที่ติดตั้งไว้ให้อัตโนมัติ หรือรัน `node scripts/prepare-dl-ocr.mjs` แยกได้ ไม่มีการดาวน์โหลดภาพหรือส่งภาพไป OCR API ภายนอก โมดูล OCR โหลดเมื่อกดอ่านภาพ ไม่เพิ่ม Firestore reads หน้าปฏิทินปกติ การโหลดครั้งแรกต้องรับ OCR assets จากเว็บเดียวกับแอป ภาษาเก็บ cache ใน browser; ไฟล์ภาพและผลชื่อไม่ถูกเก็บเป็นข้อมูลถาวร

เลือกใช้ Web Worker เพื่อให้ UI ยกเลิกได้ หยุด worker เมื่อจบ/ยกเลิก/ปิดหน้าต่าง มี timeout 2 นาที ตรวจชนิดไฟล์ ลายเซ็น และขนาดก่อนสร้าง preview จำกัด 10 MB, 12 ล้านพิกเซล, ด้านละ 6,000px, 31 แถวภาพ และ 100 รอบต่อชุด

ตัวอ่านแยกช่องจากเส้นตาราง อ่านวัน/เวลาและผู้คุมแยกกัน ช่องเวลาไม่ครบอ่านซ้ำโดยใช้ผลจากตำแหน่งและวันที่เดียวกันเท่านั้น ไม่เลื่อนเวลาจากบรรทัดถัดไปมาแทน ยังคงรายการที่อ่านไม่ได้ไว้ให้แก้และไม่บันทึกจนกว่าจะครบ

อ้างอิง [Tesseract.js API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md), [การกำหนด assets ภายใน](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md) และ [ขอบเขตโครงการ](https://github.com/naptha/tesseract.js/blob/master/README.md) OCR นี้ไม่รับ PDF โดยตรง; PDF ใช้ตัวอ่านเดิม

## ผลตรวจ

หลักฐานอยู่ใน `output/playwright/dl-image-import/`

- Unit suite **402 ผ่าน** รวม parsing, ปี พ.ศ., เวลาอ่านไม่ครบ/อ่านซ้ำ, geometry, mapping, duplicate/room conflict, atomic planning และตรวจขนาดไฟล์ก่อน decode
- ภาพจริงใน localhost: **9 แถว / 18 รอบ / 9 วัน** วันถูกครบ เวลาอ่านถูกอัตโนมัติ **16 รอบ** อีก **2 รอบต้องตรวจแก้เวลาเอง** ก่อนยืนยัน หลังแก้และใช้รายชื่อสมมติ เพิ่มได้ครบ 18 รอบในมุมมองเดือน และ Undo คืน sandbox ว่าง
- Chrome local และ Edge ผ่าน Cloudflare: ภาพสังเคราะห์อย่างละ **7 กลุ่ม** รวม actual OCR, รอบเย็น, validation/focus, review, duplicate, Undo แยก dataset, Staff controls, touch 390/768px, ยกเลิกระหว่างเริ่มโหลดและระหว่างอ่านจริง แล้วเริ่มอ่านใหม่ได้
- ไม่พบ HTTP write requests หรือการเรียก origin ภายนอกใน synthetic browser flows ไม่มีการเก็บภาพจริงหรือชื่อที่อ่านได้ไว้ใน artifact ภาพ UI ใช้ข้อมูลสมมติเท่านั้น
- Regression ปฏิทิน **11 กลุ่ม**, PDF import **4 viewport/theme cases**, targeted ESLint, native browser zoom 200% และ compatibility build แยก output ผ่าน หน้า develop ไม่แสดงเป็น workspace ใน production export
- เปรียบเทียบ `npm audit` จาก lockfile ก่อนและหลัง: รายการแจ้งเตือนเดิม 42 รายการเท่ากัน ไม่พบ advisory เพิ่มจากแพ็กเกจ OCR และไม่เปลี่ยนเวอร์ชันแพ็กเกจเดิม ไม่ได้แก้ advisory เดิมในเฟสนี้

## ข้อจำกัดและขั้นถัดไป

### แก้รายชื่อ mockup ไม่ตรงภาพ — ผลตรวจเพิ่มเติม

หลักฐานรอบแก้อยู่ใน `output/playwright/dl-image-roster/` และ regression เดิมใน `output/playwright/dl-image-import/flows/local/chrome/`

- Unit suite ล่าสุด **408 ผ่าน** เพิ่ม 6 tests สำหรับรายชื่อที่ตรวจแล้ว การใช้ ID เดิม ชื่อคล้าย/ชื่อเล่นต่างกัน ข้อมูลไม่ถูกต้อง และการเชื่อมกับ import planner
- Chrome localhost และ Edge ผ่าน Cloudflare อย่างละ **3 กลุ่ม**: OCR ภาพสังเคราะห์ → แก้ชื่อ/เพิ่มชื่อชั่วคราว → นำเข้า → รายละเอียด/แก้ไข, desktop 1440px / touch 390px dark, ชื่อซ้ำ/ชื่อคล้าย, input ไม่ล้น, สลับหน้าและเปิด import ใหม่, Undo และรีเฟรชล้าง roster ไม่มี HTTP writes หรือ origin ภายนอก
- ภาพที่ผู้ใช้แนบ `september69.png` ตรวจเฉพาะ localhost อ่านวันที่ตามเนื้อหาเป็น **พฤศจิกายน 2569** ได้ 8 กลุ่มชื่อ / 18 รอบ นำเข้าโดยใช้ ID ของรายชื่อชั่วคราวได้ เปิดรายละเอียดรอบแรกตรงกับชื่อที่เลือกครบ 3 คน และ Undo ได้ ไม่เก็บชื่อหรือภาพจริงใน artifacts ผลนี้ยืนยันการเชื่อมชื่อ ไม่ใช่การรับรองสะกดชื่อ OCR ถูกทุกคน ยังคงตรวจเวลาเอง 2 รอบตามผลเดิม
- Regression flow DL เดิม **7 กลุ่มผ่าน**, targeted ESLint และ compatibility build แยก output ผ่าน ไม่แก้ production output และไม่ deploy
- การตรวจ touch ด้วย Chromium ยังไม่ใช่ UAT บนอุปกรณ์ iPhone/Safari จริง

OCR ไม่ได้ถูกทุกช่อง ต้องตรวจภาพทุกครั้ง ภาพถ่ายเอียง ตารางคนละโครง เส้นไม่ชัด HEIC หรือเอกสารหลายหน้าไม่อยู่ในขอบเขตที่ยืนยันรองรับ การทดสอบ touch ด้วย Chromium ไม่ใช่ UAT บน Safari/iPhone/Android เครื่องจริง

ระบบตรวจอนุมัติอัตโนมัติปฏิเสธการรันภาพจริงกับ Cloudflare เนื่องจากมีรายชื่อบุคลากรบน preview ภายนอก จึงทดสอบภาพจริงเฉพาะ localhost และใช้ภาพสังเคราะห์ผ่าน Cloudflareแทน ไม่ได้พยายามเลี่ยงข้อจำกัดนี้

ให้ผู้ใช้ UAT flow นี้ก่อน แล้วจึงกำหนดเฟส adapter รายชื่อ/ข้อมูลจริง, authorization, schema, cache และ integration tests ของ production หรือเก็บตารางรูปแบบอื่นเพิ่มเติมตามที่ทีมใช้งานจริง ยังไม่มี feature route ใหม่ และ `all-pages-ready = false`
