## ช่วงวันที่ที่ยืนยันแล้วและพื้นที่ทดลองแยก

ผู้ใช้ยืนยันภาคเรียน **2/2569**: ปวช. **2 พ.ย. 2569–14 มี.ค. 2570** และ ป.ตรี **23 พ.ย. 2569–14 มี.ค. 2570** ฟอร์มนำเข้าตั้งต้นตามนี้และปรับแก้ได้ ภาคเรียนอื่นที่ยังไม่ได้กำหนดจะเป็นค่าว่าง ไม่คัดลอกช่วงเดิมไปใช้โดยอัตโนมัติ

ข้อความเตือนเดิมไม่ได้บอกว่าชนกับวิชาใด ตัวอย่างในภาพผู้ใช้คือห้อง 401 ชนกับ “ทักษะดิจิทัล” ของชุดตัวอย่าง วันที่ 2 พ.ย. 2569 เวลา 08:00–10:00 ไม่ใช่การตัดสินว่า ปวช. กับ ป.ตรีซ้ำกันเพราะช่วงภาคเรียนทับกัน ตอนนี้ข้อความระบุชื่อคู่ที่ชน ชุดข้อมูล วันที่แบบ พ.ศ. และเวลาแยกทั้งสองรายการ พร้อมแยกกรณีรายการซ้ำกับกรณีเวลาชน

- เพิ่ม **พื้นที่ทดลองนำเข้า** ที่เริ่มว่าง แยก data และ Undo จาก **ชุดตัวอย่าง** สามารถสลับกลับได้ทั้งสองทางโดยไม่ลบหรือเขียนทับอีกชุด
- จากหน้าตรวจ PDF กด **ใช้พื้นที่ทดลองแยก** ได้โดยเก็บรายการที่อ่านจากไฟล์ วันที่ และการแก้ไขไว้ เมื่อปัญหาทั้งหมดเกิดจากตารางเดิม ปุ่มท้ายฟอร์มเสนอทางนี้โดยตรง
- ยังตรวจรายการซ้ำ/เวลาชนในพื้นที่ที่เลือก และตรวจการชนกันภายในไฟล์เดิม ไม่มีการยกเว้นการตรวจเพียงเพราะเป็นคนละระดับการศึกษา
- ทดสอบไฟล์จริงที่ 390/1440: เห็นชื่อคู่ที่ชน 4 จุดในชุดตัวอย่าง → ย้ายไปพื้นที่แยกโดยไม่ลบ/ยกเลิกวิชาใด → นำเข้า **25 รายการ** → ลองไฟล์ซ้ำและถูกป้องกันทั้ง 25 → Undo เฉพาะพื้นที่แยก → ชุดตัวอย่างเดิมทั้ง 4 ยังอยู่ครบ ดู `real-file-recovery.json`
- ข้อมูลทั้งสองชุดอยู่ในหน่วยความจำของแท็บทดลองเท่านั้น ไม่ใช้ฐานข้อมูล production

## ป้องกัน hydration mismatch บน iOS

ผู้ใช้รายงานว่า text node หลัง `br` ในข้อความปีอ้างอิงถูกแยก: ฝั่ง browser เหลือเพียง “ชุดอ้างอิง ” ในขณะที่ React คาดว่าจะมีช่วงปีด้วย ข้อความเดิมเป็นค่าคงที่ ไม่ได้คำนวณจากเวลาปัจจุบัน อาการสอดคล้องกับ iOS data detection ที่แปลงตัวเลข/วันที่เป็นลิงก์ก่อน hydration ตาม [คำอธิบายของ Next.js](https://nextjs.org/docs/messages/react-hydration-error) แต่ยังไม่ได้ตรวจ DOM บน Safari เครื่องจริงเพื่อยืนยันสาเหตุโดยตรง

- ส่ง `format-detection` โดยตรงใน `head`: `telephone=no, date=no, email=no, address=no` เพื่อให้ถึง browser ก่อน parse body การทดลองใช้ metadata export ใน dev พบว่า directive อยู่ใน body จึงใช้ explicit head tag แทน
- แสดงข้อความอ้างอิงใน `span` เดียว และเขียนช่วงปีว่า “ปี พ.ศ. 2569 ถึง 2570”
- Regression test หยุดโหลด Next scripts ไว้ก่อน ตรวจว่า directive อยู่ใน head และเก็บ caption จาก server DOM แล้วจึงปล่อยให้ hydrate เปรียบเทียบข้อความหลัง hydration และตรวจการเปิด dialog / เปลี่ยนหน้า / hard reload
- Chrome local 4 และ Cloudflare 4 cases (390/1440 × light/dark) ผ่าน ไม่มี page/console errors และไม่มี HTTP errors ของเอกสาร/สคริปต์/สไตล์ ดู `hydration/local/chrome` และ `hydration/public/chrome`
- Calendar regression 11 กลุ่มและ compatibility build ผ่าน การแก้รอบนี้เป็น layout/caption ไม่มีการแก้ pure business logic หรือเพิ่มแพ็กเกจ
- WebKit ที่ติดตั้งในเครื่องรันทดสอบไม่จบและถูกหยุด บันทึกสถานะ not-verified ไว้ ไม่อ้างว่าผ่าน Safari/iPhone จริง ต้องให้ผู้ใช้ reload บน iPhone เพื่อยืนยันอีกครั้ง

## การแก้ก่อนทีมยืนยันช่วงภาคเรียน (ประวัติ)

ไฟล์แนบอ่านได้ครบ 25 รายการ แต่ช่วงภาคเรียนเริ่มเป็นค่าว่าง ปุ่มเดิมถูกปิดโดยมีเพียงข้อความรวมท้ายฟอร์ม ทำให้ผู้ใช้ที่เลื่อนมาท้าย 25 แถวไม่พบช่องที่ต้องกรอก เป็นช่องโหว่ของ flow ที่ชุดทดสอบเดิมไม่ได้ครอบคลุม: เดิมเทสต์กรอกวันที่ให้ครบก่อนลองกดบันทึก

- หากวันที่ขาดหรือผิด ปุ่มแสดง **กำหนดช่วงภาคเรียน** และบอกชื่อกลุ่ม/ช่องที่ขาด กดแล้วเลื่อนไป focus ช่องนั้นพร้อมข้อความเฉพาะช่อง ไม่ปล่อยให้เจอปุ่มปิดโดยไม่มีทางแก้
- หากเวลาชนหรือข้อมูลผิด ปุ่ม **ตรวจจุดที่ต้องแก้** จะแสดงทุกห้องและพาไปแถวแรกที่มีปัญหา หากยังไม่ได้ยืนยันการตรวจ จะพาไป checkbox ยืนยัน
- ยังไม่เดาวันสิ้นสุด ป.ตรีที่เอกสารไม่ได้ระบุ และยังไม่ข้ามการตรวจซ้ำ/ชนหรือเขียนทับตารางเดิม
- ในชุด develop เริ่มต้น ไฟล์นี้ชนกับ **ข้อมูลตัวอย่าง 4 รายการ** (ตารางเรียน 3 และสอบรายวิชา 1) ปัจจุบันใช้พื้นที่ทดลองแยกได้โดยไม่ต้องลบชุดตัวอย่าง

ผลทดสอบรอบก่อนเคยเลือกเฉพาะส่วนไม่ชนได้ 21 รายการ และลบชุดตัวอย่างก่อนทดสอบทั้ง 25 วิธีทดสอบปัจจุบันแทนที่ด้วยพื้นที่แยกตามรายละเอียดด้านบน ไม่บันทึกภาพหรือข้อความชื่อผู้สอนจากไฟล์จริงลงหลักฐาน

## สิ่งที่ทำ

- ปุ่มนำเข้าเดิมเปิดฟอร์มเลือก PDF จริง แทนการเพิ่มรายการที่กำหนดตายตัว
- อ่านข้อความและเส้นตาราง แยกช่องรวมหลายคาบ ห้อง วัน เวลา และรายละเอียด เป็นกฎตารางรายสัปดาห์
- ตรวจและแก้แต่ละรายการ เลือก/ไม่เลือก และกรองตรวจตามห้องก่อนบันทึก
- กำหนดช่วงภาคเรียนแยก ปวช. กับ ป.ตรี/อื่น ๆ โดยชัดเจน ไม่เดาวันสิ้นสุดจากเอกสารที่ระบุไม่ครบ เปลี่ยนกลุ่มแต่ละแถวได้
- ข้อความ “งดให้บริการ” ไม่สร้างกฎปิดห้อง วันหยุดยังแสดงในปฏิทินและไม่ยกเลิกคาบโดยอัตโนมัติ
- ตรวจซ้ำและเวลาชนกับตารางเรียน/สอบเดิมทุกวันที่เกิดคาบ รวมถึงการชนกันภายในชุดนำเข้า หากรายการที่เลือกมีปัญหา จะไม่เพิ่มบางส่วน
- บันทึกในข้อมูลตัวอย่างในหน่วยความจำเป็นชุดเดียว เลิกทำได้ด้วย Undo ล่าสุด การเพิ่มและแก้ด้วยฟอร์มเดิมยังใช้ได้
- Staff ไม่มีสิทธิ์นำเข้า PDF ไม่สร้าง worklogs และไม่เพิ่มยอดสถิติงาน
- อ่านไฟล์ใน browser ไม่มีการอัปโหลดหรือเรียก CDN ยกเลิก/ปิด dialog จะยุติการอ่าน
- ใช้ shared QuickLiquid A และสี semantic เดิม ช่องกรอก mobile มีขนาดอย่างน้อย 16px

## รูปแบบที่รองรับและข้อจำกัด

รองรับ PDF ข้อความและเส้นตารางลักษณะเดียวกับตัวอย่างห้อง 401/402/406/407 ไม่เกิน 10 MB, 5 หน้า, 200 แถว การเปลี่ยนฟอนต์/โครงสร้างเอกสารต้องตรวจผลก่อนนำเข้า ไฟล์ภาพ, PDF สแกน, ตารางที่หมุน, PDF เข้ารหัส, การอ่านตารางสอบ DL จากภาพ และระบบ production อยู่นอกขอบเขตนี้ หน้า/ส่วนที่อ่านไม่ได้มีคำเตือน ไม่มีการอ้างว่าอ่าน PDF ได้ทุกแบบ

แถวที่มีคำว่า ปวช. จะได้กลุ่ม ปวช. ส่วนอื่นเริ่มที่ ป.ตรี/อื่น ๆ **เป็นคำแนะนำให้ตรวจแก้** ไม่ใช่การยืนยันระดับการศึกษา ผู้ใช้ต้องตรวจยืนยันกลุ่ม วันเริ่ม/สิ้นสุด และต้นฉบับก่อนบันทึก ภาคเรียนที่ไม่มีค่าเริ่มต้นต้องระบุช่วงวันที่เอง

ตัวอ่านใช้ vector API ของ PDF.js 5.6.205 จึงตรึงเวอร์ชันและต้องทดสอบตัวแยกเส้นใหม่ก่อนอัปเกรด [เอกสาร Mozilla PDF.js](https://mozilla.github.io/pdf.js/getting_started/)

## หลักฐานตรวจสอบ

- Unit suite: **361/361 ผ่าน**, เพิ่ม 19 ข้อสำหรับ geometry, ปี พ.ศ., ขอบเขตวันที่, ชน/ซ้ำ, การป้องกันบันทึกบางส่วน, ช่องวันที่ที่ขาด, ค่าเริ่มต้นเฉพาะภาคเรียนที่ยืนยัน และการแยกคู่ที่ชนภายใน/ภายนอกชุดนำเข้า
- PDF ต้นฉบับ: ตรวจภาพเทียบผล พบ **25 ตารางรายสัปดาห์** — ห้อง 401: 9, 402: 7, 406: 2, 407: 7 ไม่มีคำเตือน บันทึกหลักฐานเฉพาะจำนวนและช่วงเวลา ไม่มีชื่อผู้สอน/รายละเอียดจริงใน fixtures หรือรายงาน
- Edge และ Chrome: browser/file/worker จริง **8 cases** (1440/390 × light/dark × 2 browsers) โดยใช้ assets ที่แอปเสิร์ฟจริง ตรวจแก้ชื่อ, เวลาในช่องรวม, ไม่นำเข้า annotation, ยืนยันวันที่, Cancel ระหว่างโหลดตัวอ่าน, บันทึกเป็นชุด, ป้องกันซ้ำ, Undo และ Staff guard
- เพิ่มการจำลองกดต่อจากท้ายฟอร์มเมื่อยังไม่ได้กรอกวันเริ่ม/สิ้นสุด และการพาไป checkbox/รายการชน พร้อมทดสอบไฟล์จริงเพิ่ม **2 cases** ตามรายละเอียดข้างต้น
- Cloudflare: **4 cases** ใน Chrome (1440/390 × light/dark) ผ่าน flow เดียวกันด้วย assets ของแอปจริง ไม่มี page/console errors, HTTP errors ของเอกสาร/สคริปต์/สไตล์ หรือการเรียก origin ภายนอก รวม browser cases หลังติดตั้ง **12 cases** หลักฐานใน `browser/edge`, `browser/chrome` และ `public/chrome`
- การทดสอบก่อนอนุมัติติดตั้งเคยใช้ runtime ของเครื่องมือทดสอบ ผลปัจจุบันแทนที่ด้วยการตรวจแอปที่ติดตั้ง dependency แล้วทั้งหมด
- Regression ปฏิทินเดิม: **11 กลุ่มผ่าน** รวม DL 75 คน/รอบเย็น, recurrence, keyboard, filters, 4 views และ touch widths 375/390/430/768
- Targeted ESLint ผ่าน และ compatibility export ผ่านใน `.ui-build-check`; หน้า develop ไม่ render ใน production export
- ยังไม่ทดสอบบน Safari/iPhone/Android เครื่องจริง และยังไม่ทำ UAT โดยผู้ใช้ ไม่มีการ deploy, push หรือเชื่อมฐานข้อมูลจริง

ดูหลักฐานที่ `output/playwright/classroom-pdf-import/` เฉพาะรายงาน, screenshot ข้อมูลสังเคราะห์ และ PDF สังเคราะห์ ภาพ render ต้นฉบับเป็นไฟล์ private ที่ถูก ignore ไม่อยู่ใน commit

## การติดตั้งและเริ่ม develop

1. เพิ่มแพ็กเกจเวอร์ชันที่ตรึงไว้และ lockfile ด้วย npm จากนั้นดาวน์โหลด tarball ทางการ ตรวจ SHA-512 ตรงกับ lockfile ก่อนติดตั้งเฉพาะ PDF.js ไม่มีการรัน install scripts หรือเพิ่ม optional dependencies ของแพ็กเกจนี้ และแพ็กเกจ optional เดิมทั้ง 77 รายการยังอยู่ในเวอร์ชันเดิม ดู `dependency-install.json`
2. รัน `node scripts/prepare-classroom-pdf.mjs` เพื่อคัดลอก module/worker รุ่นเดียวกันและ LICENSE ไป `frontend/public/dev-pdfjs/` ซึ่งเป็น generated assets และถูก ignore จาก Git
3. เริ่ม `node scripts/dev-ui.mjs` ใหม่ สคริปต์จะเตรียม assets ให้อัตโนมัติเมื่อพบ dependency ที่ตรงเวอร์ชัน
4. รัน `scripts/verify-classroom-pdf.cjs` **โดยไม่ส่ง argument runtimePdf** เพื่อทดสอบ assets ของแอปจริง ผลตรวจ local และ Cloudflare ผ่านแล้ว ขั้นต่อไปคือ UAT บนอุปกรณ์จริงของผู้ใช้

หากยังไม่ติดตั้ง reader หน้าปฏิทินและฟอร์มเดิมใช้งานต่อได้ การเลือก PDF จะแจ้งว่าตัวอ่านยังไม่พร้อม ไม่มีผลลัพธ์นำเข้าจำลองแทนให้เข้าใจผิด

ขั้นต่อไปหลังผ่าน UAT ของเฟสนี้: จึงพิจารณา adapter/สิทธิ์/ธุรกรรมกับข้อมูลจริงแยกเฟส ตามการอนุมัติของผู้ใช้
