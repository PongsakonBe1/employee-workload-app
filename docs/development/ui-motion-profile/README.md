# ตรวจ UI และแอนิเมชันของ labboy

ใช้ commit `d7053d8` เป็นฐาน เปรียบเทียบกับแบบ R07 และใช้ [Apple HIG Motion](https://developer.apple.com/design/human-interface-guidelines/motion), [Icons](https://developer.apple.com/design/human-interface-guidelines/icons), [Materials](https://developer.apple.com/design/human-interface-guidelines/materials) และ [UI Kit รุ่น 27](https://developer.apple.com/design/whats-new/) เป็นแนวทางสำหรับเว็บ/PWA

## ผลตรวจตามหน้า

| หน้า | สิ่งที่พบและขอบเขตที่ตรวจ |
|---|---|
| หน้าแรก `/` | ตรวจจุดเข้าแอปและเส้นทางเปลี่ยนหน้า การลงชื่อเข้าใช้ Google ทดสอบแยกจากชุดนี้ |
| เข้าสู่ระบบ `/login` | เปิดได้และปุ่ม Google ยังมีข้อความ ใช้พื้นและลำดับเนื้อหาเดิม |
| รออนุมัติ `/pending` | ตรวจเส้นทางและ shell การอนุมัติบัญชีเป็นคนละ flow |
| บันทึกงาน `/worklogs/new` | ปรับขอบ สี และไอคอนการ์ด ยืนยันมือถือเห็นหกการ์ดเหนือ Dock และ PC แสดงเก้าการ์ด |
| บันทึกของทีม `/admin/record` | ใช้ Quick Log และ dialog ชุดเดียวกับ Staff การจัดชื่อเป็นอีกชุดตรวจรับ |
| ประวัติงาน `/worklogs` | ตรวจการเปิดหน้าหลักและพื้นที่หน้าจอ ตารางและตัวกรองยังใช้ flow เดิม |
| ปฏิทิน `/calendar` | ตรวจพื้นที่ปฏิทินและ shell การเขียนตารางและการนำเข้าเป็นคนละชุดทดสอบ |
| ห้องและทรัพยากร `/resources` | ตรวจโครงหน้าและการเลื่อน ข้อมูลสถานะจริงต้องยืนยันใน staging |
| ภาพรวม `/dashboard` | ตรวจการแสดงโครงหน้า การตรวจตัวเลขรายงานเป็นคนละชุด |
| โปรไฟล์ `/profile` | พับข้อมูลบัญชีเพื่อให้เห็นสถิติเร็วขึ้น เลือกช่วงเวลาและเปิดอันดับเพื่ออ่านบันทึกได้ |
| ส่งออก `/export` | ตรวจโครงฟอร์มและพื้นที่หน้าจอ การดาวน์โหลดข้อมูลอยู่นอกการตรวจ UI รอบนี้ |
| คู่มือ `/help` | ตรวจว่าอ่านได้ในความกว้างมือถือและ PC |
| หน้าเริ่มผู้ดูแล `/admin` | ตรวจเส้นทางเข้าและ shell ด้วยบัญชีสังเคราะห์ |
| จัดการผู้ใช้ `/admin/users` | ตรวจการแสดงหน้าและ control ร่วม การเปลี่ยนบทบาทอยู่นอกชุดนี้ |
| เทมเพลต `/admin/templates` | ตรวจโครงรายการ การแก้เทมเพลตอยู่นอกชุดนี้ |
| จัดการอุปกรณ์ `/admin/equipment-items` | ตรวจตรารางและพื้นที่หน้าจอ การย้ายอุปกรณ์อยู่นอกชุดนี้ |
| สภาพอุปกรณ์ `/admin/equipment-health` | ตรวจโครงรายงานและ shell ใช้สถานะสังเคราะห์ในการตรวจ UI |
| จัดการระบบ `/admin/system` | ตรวจโครงหน้า การอนุมัติคำขอจริงอยู่นอกชุดนี้ |

| เครื่องมือ cleanup `/admin/cleanup` | ตรวจโครงหน้า ใช้การอ่านเท่านั้น |
| ตั้งค่าระบบ `/admin/settings` | ตรวจโครงหน้า ใช้การอ่านเท่านั้น |
| ประวัติการใช้งาน `/admin/audit-logs` | ซอร์สระบุว่าหน้านี้ใช้ข้อมูลตัวอย่าง ให้เทียบกับแหล่ง audit จริงก่อนพัฒนาประวัติการใช้งานต่อ |

## หลักฐานและขอบเขต

- เปิด 24 เส้นทางบน PC และมือถือ ผลตรวจไม่พบหน้าที่เลื่อนแนวนอนทั้งหน้า การเปิดสี่หน้าที่สุ่มกลับไปหน้าเข้าสู่ระบบตอนตรวจพร้อมกันผ่านเมื่อตรวจซ้ำทีละหน้าใน session เดิม
- ภาพก่อน–หลังของบันทึกงานและโปรไฟล์ รวมภาพหน้าต่างยืนยันและผลตรวจเส้นทาง อยู่ใน `output/playwright/worklog-workspace-smoke/` ของ worktree ชุดนี้ ใช้ข้อมูลสังเคราะห์ใน Firebase Emulator
- การตรวจแอนิเมชันเน้นระยะเวลา การกด Escape และการคืนโฟกัส ใช้เบราว์เซอร์บน Windows จำลองหน้าจอมือถือ การทดสอบ PWA และ VoiceOver บน iPhone จริงเป็นงานตรวจรับใน staging
- หน้าปฏิทินและทรัพยากรในการตรวจนี้ใช้ข้อมูลตัวอย่างและสถานะเมื่อ API ไม่พร้อม ใช้ผลตรวจเฉพาะการจัดวาง การอ่านข้อมูลจริงและสถานะบัญชี FCM ต้องตรวจผ่านสภาพแวดล้อมที่เปิดบริการ

## แถบไฮไลต์ของเมนูและตัวเลือก

- เมนูล่างมือถือเลื่อนแถบไฮไลต์ทันทีเมื่อแตะ ตัวเลือกมุมมองและช่วงเวลาที่เลือกได้ครั้งละหนึ่งตัวใช้จังหวะเดียวกันประมาณ 200 มิลลิวินาที
- ลิงก์และปุ่มเดิมยังรับการแตะและคีย์บอร์ด สถานะที่โปรแกรมอ่านหน้าจอเห็นเปลี่ยนตามหน้าหรือตัวเลือกที่เปิดจริง เมื่อเปิด Reduce Motion ใช้สถานะเลือกแบบทันที
- มีตัวอย่างท่าลากใต้ flag `NEXT_PUBLIC_MOBILE_TAB_SCRUB_PREVIEW=1` สำหรับ development, Emulator และ `labboy-workload-app-staging` ส่วน production เปิดด้วย `--mobile-tab-scrub` เมื่อรัน `scripts/build-production-hosting.mjs` ค่าเริ่มต้นของทั้งสองแบบคือปิด
- เริ่มกดที่แท็บปัจจุบันแล้วลากแนวนอนหลังประมาณ 180 มิลลิวินาที แถบติดตามนิ้วและเปิดหน้าที่ปล่อยลงบนแท็บ ส่วนการลากออกจากเมนู การเลื่อนแนวตั้ง และการยกเลิกสัมผัสจะคืนแถบให้หน้าปัจจุบัน
- ตรวจบน iPhone จริงใน Safari และ PWA ก่อนเปิดใช้ โดยลองแตะปกติ ลากแล้วปล่อย ลากออกนอกเมนู เลื่อนแนวตั้ง และเปิด Reduce Motion
- ใน Edge ที่จำลองสัมผัส แถบคืนตำแหน่งเมื่อลากออก แต่เบราว์เซอร์ส่ง `pointerdown` และ `pointerup` โดยขาด `click` ในการแตะครั้งแรกหลังยกเลิก กรณีนี้ต้องตรวจบน iPhone จริงก่อนเปิด flag ให้ผู้ใช้
- ผู้ทดสอบยืนยันผลจาก Safari และ PWA บน iPhone ผ่านหน้า Hosting preview แยกที่ใช้ไฟล์ควบคุมการลากเดียวกัน และยืนยันการทดสอบหลังเข้าสู่ระบบในแอป Hosting staging ด้วย

เปิดตัวอย่างใน build สำหรับ Emulator ด้วย `node scripts/worklog-workspace-smoke.mjs build --analytics --scrub-preview`
